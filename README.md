# 보안길잡이 AI v0.2 · GitHub Pages

2026 공공 AI 대전환 챌린지 팀 소개용 브라우저 기반 프로토타입.
기관별 보안 서류 양식과 처리 절차를 설정하여 신청자 질문, 문서, 검토 흐름에 연결한다.

## 실행 구조

별도 의존성 설치나 빌드가 필요 없는 정적 HTML/CSS/JavaScript 앱이다.
GitHub Pages 배포 폴더는 docs/이다. 소스 변경을 main 브랜치에 반영하면 Pages가 다시 배포한다.

- config-engine.js: 기관 설정, 스냅샷, 조건 분기, 템플릿 텍스트 읽기, 필수값 검사
- admin-ui.js: 기관 관리자 시연 화면과 양식/절차 편집
- app.js: 신청자 흐름, 동적 문서, 모의 검토, HTML 패키지 출력
- org-settings.css: 기관 설정 및 동적 흐름 UI

## GitHub Pages 배포

이 저장소는 서버나 빌드 과정 없이 GitHub Pages에서 실행할 수 있다.

1. 저장소의 **Settings → Pages**로 이동한다.
2. **Build and deployment → Source**를 **Deploy from a branch**로 설정한다.
3. **Branch: main**, **Folder: /docs**를 선택하고 저장한다.
4. 배포가 완료되면 같은 화면의 사이트 주소를 연다.

`docs/.nojekyll`은 정적 파일을 그대로 게시하기 위한 설정이다. 모든 앱 리소스는 상대 경로를 사용하므로 프로젝트 저장소의 하위 주소에서도 동작한다.

GitHub Pages 사이트는 일반적으로 공개된다. 현재 소스에는 가상 기관·합성 시연 데이터만 포함되어 있다. 실제 업무 데이터, API 키, 기관 내부 설정 파일은 저장소에 추가하지 않는다.

브라우저 저장소는 도메인별로 분리된다. 기존 시연 사이트에서 수정한 기관 설정은 새 GitHub Pages 주소로 자동 이전되지 않는다.

## 로컬 실행

Python 3이 설치된 환경에서 저장소 폴더의 터미널을 열고 다음 명령을 실행한다.

```bash
python -m http.server 8080 --directory docs
```

브라우저에서 `http://localhost:8080/`을 연다.

## 팀 시연 순서

1. 사이드바에서 기관 A 또는 B를 선택한다.
2. 기관별 설정 → 기관 양식 관리에서 양식을 직접 편집하거나 파일/텍스트를 등록한다.
3. 모의 AI 항목 인식 → 공통 정보 연결 또는 기관 전용 항목 지정 → 필수 여부와 항목 순서 확인.
4. 항목 연결 확인 체크 후 설정을 게시한다.
5. 처리 절차 설정에서 단계 순서, 담당 역할, 조건을 수정하여 게시한다.
6. 서비스 소개 → 샘플 프로젝트 → 분석 → 개인정보 여부 응답 → 기관 추가 질문 입력.
7. 문서 생성 → 정합성 점검 → 모의 검토 요청 → 단계별 완료 → 최종 확인 → HTML 패키지 생성.

기관 A 기본 절차는 인프라 후 보안 순차 검토이다.
기관 B는 보안·인프라 병렬 검토, 개인정보 처리 시 추가 검토, 최종 승인 역할이다.
같은 단계의 모든 담당 역할이 완료되어야 다음 단계가 열린다.
조건이 미확정이면 생략하지 않고 확인 대상으로 유지한다.

## 설정과 데이터

- 관리자 초안과 게시본은 분리된다. 미게시 수정은 신청자에게 반영되지 않는다.
- 분석 시작 시 기관 설정 버전이 해당 신청에 고정된다.
- 기존 신청에 최신 설정을 적용하려면 명시적으로 전환해야 하며, 문서와 검토 상태가 초기화된다.
- 프로젝트 정보 수정도 문서·검토·최종 확인 상태를 초기화한다.
- 설정 저장/게시 시 브라우저 localStorage를 사용한다. 기관 간 서버 격리나 사용자 권한 검증은 구현하지 않았다.
- 프로젝트 입력, 원본 파일, 검토 이력은 서버에 저장하거나 전송하지 않는다.
- 브라우저 새로고침은 프로젝트 시연을 초기화하되 저장된 기관 설정은 유지한다.

## 지원 범위 및 한계

양식 등록: TXT, MD, JSON, HWPX, DOCX (최대 5MB).
HWPX/DOCX는 ZIP 내부 XML의 텍스트 항목만 읽으며 원본 표 병합·글꼴·페이지 배치를 복제하지 않는다.
PDF, 구형 HWP, 이미지·스캔 문서는 항목명을 텍스트로 붙여 넣어야 한다.
암호화·손상·과도한 압축/크기 문서는 거부한다.
일부 구형 브라우저는 압축 문서 읽기가 지원되지 않아 텍스트 입력을 사용해야 한다.

양식 인식은 명시된 항목명 별칭과 규칙을 사용하는 모의 AI이다.
실제 LLM, 정책 RAG, 전자결재, 알림 전송, 공식 보안 승인과 연결되지 않는다.
서식 항목·순서·필수값·표/번호 레이아웃을 재구성하며 출력은 시연용 HTML이다.
미확정 값은 지어내지 않으며 필수값 누락은 최종 패키지 생성을 제한한다.
IP는 예시 문자열이며 네트워크 가용성·정책 적합성 검증을 수행하지 않는다.
실제 비공개 보안 정보나 개인정보를 입력하지 않는다.

## 검사

Node.js 24 기준:

    node --check docs/app.js
    node --check docs/config-engine.js
    node --check docs/admin-ui.js
    node --test --test-isolation=none tests/config-engine.test.cjs

자동 테스트는 기관별 분리, 스냅샷, 조건 분기, 순차·병렬 잠금, 필수 항목,
텍스트/JSON 읽기, 파일 오류, 손상 설정 복원, 관리자 blur 회귀를 검사한다.

브라우저 확인: A 맞춤 항목 추가·게시·기존 신청 버전 고정·명시적 전환,
필수값 누락, A 순차 검토와 보완, B 병렬 합류와 개인정보 분기,
검토 후 입력 변경 무효화, 최종 HTML 생성, HWPX 텍스트 추출.

tests/fixtures의 HWPX/DOCX는 ZIP/XML 추출기를 검증하는 최소 합성 fixture이다.
일반 편집기에서 사용할 완전한 문서 견본은 아니다. 실제 등록 예시는 앱의
등록용 샘플 양식 다운로드로 제공하는 TXT 파일을 사용한다.
