# 보안길잡이 AI v0.4 · KRDS 기반 프로토타입

기관별 보안 서류 작성·검토·보완·최종 처리를 체험하는 브라우저 기반 팀 시연용 프로토타입입니다.

## 팀 시연 주소

**https://pocketmun1216.github.io/secureflow-2026-prototype/**

별도 설치·로그인·API 키 없이 이용합니다. 첫 화면 상단의 **KRDS 기반 · v0.4** 표시로 버전을 확인하세요. 이전 화면이 보이면 강력 새로고침을 하세요.

## 권장 체험 순서

1. 신청 현황에서 **새 시연 프로젝트**를 선택합니다. 처음부터 입력하려면 **새 보안 신청 → 예시 채우기 → 분석·인터뷰 시작**을 사용합니다.
2. 인터뷰 답변을 확인하고 **담당자 협의 요청**을 누릅니다. 모르는 기술정보는 **확인 필요**로 남깁니다.
3. **시연 역할 전환**에서 ICT인프라 담당자를 선택한 뒤 **합성 기술정보 입력 → 확인 정보 저장 → 협의 완료**를 진행합니다.
4. 정보보안 담당자로 전환해 정보를 보충·저장합니다. 필요하면 보완 요청을 추가하고, **협의 완료 → 초안 생성·사용자에게 전달**을 누릅니다.
5. 신청자로 전환해 보완 답변을 저장하고, 서류별로 미리보기와 확인 표시를 진행한 뒤 최종 제출합니다.
6. 담당자별 최종 검토를 완료한 후, 각 서류의 적용 결과를 별도로 기록합니다. 실제 장비나 기관 시스템은 변경되지 않습니다.

가상기관 A는 인프라 → 정보보안 순차 검토, 가상기관 B는 병렬 검토와 개인정보 조건부 검토를 예시로 제공합니다.

## 기관별 설정

기관 관리자 또는 정보보안 담당자 역할에서 **기관 설정**을 엽니다.

- 필수 항목·인터뷰: 질문 이름, 작성 담당자, 확인 시점, 필수 여부와 기관 전용 질문을 설정합니다.
- 신청 양식: 서류 이름, 사용 조건, 처리 담당자, 포함 항목을 설정하고 빈 양식의 텍스트 항목을 연결합니다.
- 처리 절차: 네 단계의 표시 이름과 담당자 검토 순서·병렬 역할·실행 조건을 변경합니다.
- 초안 저장과 설정 게시를 구분합니다. 게시한 새 설정은 이후 생성하는 신청에 적용되며 기존 신청은 시작 당시 설정을 유지합니다.

## 현재 시연 범위와 주의사항

분석·인터뷰·요약은 **규칙 기반 모의 AI**입니다. 실제 LLM, 사용자 인증, 기관별 서버 격리, 담당자 알림, 전자결재, 공식 제출·보안 승인, 방화벽 적용은 연결되지 않았습니다. 역할 전환은 시연 기능이며 보안 통제가 아닙니다.

**실제 개인정보·운영 IP·계정·API 키·비공개 사업계획서와 보안 양식을 입력하지 마세요.** 제공된 합성 데이터로만 체험하세요.

입력 텍스트, 기관 설정, 신청과 처리 이력은 현재 브라우저의 localStorage(`secureflow_krds_v04`)에 저장됩니다. 원본 첨부파일 자체는 보관하지 않습니다. 다른 팀원·기기·브라우저와 자동 공유되지 않으며 이전 v0.2의 저장 데이터도 자동 이전하지 않습니다.

파일 입력은 TXT·MD·JSON·DOCX·HWPX, 최대 5MB입니다. DOCX·HWPX는 텍스트만 읽으며 원본 표 병합·글꼴·페이지 배치를 복원하지 않습니다. PDF·이미지·구형 HWP는 내용을 텍스트로 입력해야 합니다. 출력은 시연용 HTML이며 공식 접수 서식 호환성을 보증하지 않습니다.

## 실행과 배포

```sh
python -m http.server 8080 --directory docs
```

브라우저에서 `http://localhost:8080/`을 엽니다. 별도 패키지 설치나 빌드 과정이 없습니다.

GitHub Pages는 기존 **main / docs** 배포 구성을 사용합니다. 화면 파일의 상대 경로를 유지하므로 저장소 하위 주소에서도 동작합니다. `docs/index.html`은 캐시 충돌을 줄이기 위한 버전 쿼리를 사용합니다. `docs/deployment.json`에는 버전과 핵심 원본 파일의 Git blob SHA-1이 기록되어 있습니다.

현재 진입점이 사용하는 파일:

```text
docs/index.html      KRDS 화면 진입점
docs/styles.css      KRDS 기반 반응형 스타일
docs/engine.js       기관 설정·정보 검증·워크플로
docs/app.js          신청자·담당자·관리자 화면
docs/.nojekyll       정적 Pages 배포
docs/deployment.json 배포 버전과 원본 해시
```

이전 v0.2의 `config-engine.js`, `admin-ui.js`, `org-settings.css` 등은 기존 자료 보존을 위해 남아 있지만 새 진입점에서는 로드하지 않습니다. 이전 버전 전체는 Git 커밋 이력에서도 확인할 수 있습니다. 원치 않는 파일 삭제나 저장소 공개 범위 변경은 하지 않습니다.

## 검사

```sh
node --check docs/engine.js
node --check docs/app.js
node --test tests/krds-engine.test.cjs
```

배포 준비 시 업무 로직 40개 단위 테스트와 원본 패키지의 Chromium 상호작용 검증 35개를 다시 실행해 통과했습니다. 구체적인 범위와 한계는 `KRDS_TEST_REPORT.md`를 참고하세요. 이는 실제 LLM 정확도, 운영 보안, 접근성 인증 또는 공식 승인 절차 검증을 의미하지 않습니다.
